# CP-to-CP / VMAT sector technical metrics — исследовательская версия 0.5

**Фокус проекта — технический анализ RTPLAN, а не DVH.** Вход: локальный DICOM RTPLAN MLCX. RTSTRUCT и RTDOSE для этих расчётов не нужны. Выход: обезличенная таблица переходов и угловых секторов.

## Формулы по каждому соседнему CP

CP i, i+1; положения листьев двух банков L_i[k], R_i[k] в мм.

* \`delta_cmw = max(0, CMW[i+1] − CMW[i])\`;
* \`delta_mu = BeamMeterset × delta_cmw / FinalCumulativeMetersetWeight\`; при неизвестном BeamMeterset либо нулевом финальном CMW возвращается null. **Это не \`BeamMeterset × ΔCMW\` без нормировки**.
* \`max_single_leaf_step_mm = max_k(|L[i+1,k]−L[i,k]|, |R[i+1,k]−R[i,k]|)\` — максимум среди всех пар, в том числе прикрытых jaws. Не физическая скорость.
* \`max_active_leaf_step_mm\` — максимум только среди пар, открытых и экспонированных Y jaws хотя бы в одном из CP.
* \`total_leaf_step_mm = Σ_k (|ΔL[k]|+|ΔR[k]|)\` — сумма всех абсолютных движений обоих банков.
* \`max_leaf_mm_per_mu = max_single_leaf_step_mm / delta_mu\` только при delta_mu > 0; ΔMU=0 отдельно маркируется.
* \`gantry_sweep_shortest_deg\` — абсолютная кратчайшая угловая разность двух CP с переходом через 0/360. Направление GantryRotationDirection пока не учитывается; при 180° выбор пути неоднозначен. Не позволяет реконструировать возможный полный оборот между CP.
* \`max_leaf_mm_per_degree = max_single_leaf_step_mm / gantry_sweep_shortest_deg\` только при изменении gantry.
* \`leaf_motion_without_incremental_mu\` — листовые координаты изменились при ΔCMW=0; это **не автоматическая ошибка** — возможно перепозиционирование при выключенном пучке.
* \`gantry_motion_without_incremental_mu\` — движение gantry при ΔCMW=0; также не автоматическая ошибка.

**Названия индикаторов преднамеренно не содержат слова "velocity" или "speed":** временная шкала не определена CP-геометрией.

## VMAT sectors

Полный круг делится на N секторов шириной 360/N (по умолчанию 30°). Интервал назначается в один сектор по **угловой середине кратчайшего перехода** с учётом wrap. Суммируются ΔMU, величины изменения координат, угловой sweep. Доступны \`sum_delta_mu\`, \`sum_gantry_sweep_deg\`, \`sum_leaf_step_mm\`, \`max_single_leaf_step_mm\`, \`max_leaf_mm_per_mu\`, \`leaf_step_mm_per_mu\`, \`mu_per_swept_degree\` и количество переходов с ΔMU=0 при движении MLC. Статичный gantry **не порождает** VMAT-секторов.

Угловая середина — **приближение для технической диагностики**: длинный CP-переход может пересекать границы секторов, и вся его нагрузка в этой версии относится к одному сектору. Это не beamlet-доза и не реконструкция флюенса. Удалять сектор на основании одной такой таблицы **нельзя**: необходимо учитывать его дозовый вклад и покрытие мишени.

## Ограничения ускорителя (опционально)

При вводе **проверенных локально** верхних ограничений:
- максимальная скорость лепестка \`Vleaf\`, мм/с;
- максимальная скорость gantry \`Vgantry\`, °/с;
- максимальная мощность дозы \`Rmax\`, MU/мин;

\`t_min_CP = max(max_leaf_step_mm/Vleaf, delta_theta/Vgantry, 60*delta_mu/Rmax)\` с пропуском незаданных слагаемых. Сумма CP-переходов даёт идеализированную **нижнюю** оценку времени из указанных ограничений. Используется максимальное смещение одного лепестка и не учитываются ускорения, retardation, interlocks, остановки, transmission и особенности контроллера. Не является проверкой фактической скорости или успешности отпуска. Без введённых ограничений время = null.

## Запуск и защита данных

\`\`\`bash
python -m pip install -e ".[test,ui]"
rtpi-transitions /secure/RTPLAN.dcm --output-dir /secure/local-analysis
\`\`\`

Появляются три файла:

1. \`rtpi_beam_transition_summary.csv\`: по одному ряду на луч;
2. \`rtpi_cp_transitions.csv\`: все соседние CP;
3. \`rtpi_vmat_sectors.csv\`: только сектора вращающихся лучей.

Выход содержит только индексы плана и поля, числа и контролируемые флаги; PatientID, имена, названия файлов и DICOM UID **не экспортируются**. Однако связка индексов с реальной выборкой делает результат конфиденциальной исследовательской информацией. Не публиковать CSV в GitHub, Vercel или открытых чатах.

## Интерпретация

Сортировка по \`max_leaf_mm_per_mu\` показывает переходы с большим движением и малым ΔMU, а \`max_single_leaf_step_mm\` — потенциально значительные сдвиги даже за большой ΔMU. Они не универсальные клинические пороги. Для прогнозирования gamma и технической доставляемости потребуются машинно-специфические ограничения, измеренные QA и/или trajectory/record&verify логи с независимой валидацией.
